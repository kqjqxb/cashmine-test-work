# PLAN — CashMine payback slice (deadline 13:00 UTC, 2026-10-21)

## Goal
Expo (TS, expo-router) web app for a ~390px phone screen: payback balances + claiming them.
Priority: Balances > Claim > Tests > Activity. Fewer things done correctly beats everything half-done.

## Invariants (never break)
- Amounts: bigint in smallest units via src/lib/money.ts. No JS number / parseFloat for asset amounts. Parse API strings once at the boundary; malformed amount from API = error, never silent 0.
- API base URL only in src/config.ts.
- Token: entered by user at runtime, stored in browser storage, changeable. Never in code, repo, logs or build. $CASHMINE_TOKEN in .env is for curl checks only.
- API is flaky (429/500/503/504, slow). GETs retry with backoff + Retry-After. POST /v1/claims is never retried blindly — only with the SAME Idempotency-Key and SAME body.
- 504 on claim = outcome unknown → never show "failed", never generate a new key for the same attempt.
- Every screen has loading / error+retry / empty states, designed for 390px.
- Style: CashMine look (theme file: cream bg, white cards, orange gradient pill buttons).

## Decisions log
(append: decision — alternatives — why)

- Step 1: Test runner = jest-expo preset — plain jest + ts-jest/babel config — Expo's SDK 58 docs recommend it; babel-preset-expo already compiles TS (no extra config); will also cover component tests later.
- Step 1: Added `parseSignedAmount` — reuse unsigned parser and handle sign in UI — API docs say activity `amount` is signed (negative for reversals/claims); strict unsigned parser would reject it.
- Step 1: Decimal places counted as written ("1.0" with 0 decimals = too many decimals) — trim trailing zeros before checking — matches the API rule literally and what the user typed; no hidden normalization.
- Step 1: User input leniency = trim + replace the first comma with a dot; "1,000.5" and inner spaces rejected — guess thousand separators — guessing a separator could silently change an amount by 1000×.
- Step 1: USD as exact `{units, scale}` Decimal; total rescales to the max scale before summing, rounded half away from zero only in `formatUsd` — round per asset / use float — per-asset rounding drifts (3 × $0.004 → $0.00 instead of $0.01).
- Step 1: Malformed `usdPrice` → `computeUsd` returns null and `totalUsd` returns null (total unknown) — skip that asset / treat as 0 — a partial total would look correct but be wrong.
- Step 1: `validateClaimAmount` takes minAmount/available/fee as bigint — take raw API strings — API strings are parsed once at the boundary (invariant), validation stays pure.
- Step 1: Jest packages moved to devDependencies; `"types": ["jest"]` in tsconfig (TS 6 no longer auto-includes @types) — n/a — needed for typecheck of test files.
- Step 1: Kept `eslint.config.js` + eslint deps generated by the first `npx expo lint` — n/a — AGENTS.md requires lint before finishing a task.
- Step 1: Pre-existing template errors (3 tsc, 1 lint) left untouched — fix now — template screens are out of scope until step 2 cleanup.
- Step 2: USD total = **available only** ("Available to claim") — available+pending+claiming — pending can still be reversed by the exchange (reversals exist) and claiming is already leaving the account; the headline should be money the user can act on now. Pending/claiming are shown per asset.
- Step 2: Freshness age = client `Date.now() - asOf`, clamped at 0 — compute server clock skew from the `Date` header — `Date` is not a CORS-exposed header, so the browser can't read it; a wrong device clock skews the label (accepted).
- Step 2: "Stale" pill when age > 60s or the last refresh failed; old data stays visible with a red banner + Retry.
- Step 2: Only one balances request in flight; the interval/refresh button is a no-op while one runs; leaving the screen aborts it (abort is not shown as an error).
- Step 2: Retry policy (GET only): max 3 attempts; 429 waits `retryAfterMs` (body) or `Retry-After` (header), but if it asks for > 10s we surface the error instead of hanging; 500/503/504/network/client-timeout use 400ms·2^n + jitter — fixed delay / unlimited retries — bounded worst case, no lockstep retries.
- Step 2: 10s client timeout → code CLIENT_TIMEOUT (status 0). On POST /v1/claims this must be treated like 504 (outcome unknown) — handled in step 6.
- Step 2: Client-side errors use status 0 with codes NETWORK / CLIENT_TIMEOUT / ABORTED / BAD_RESPONSE — separate error classes — one ApiError type keeps UI branching simple.
- Step 2: `usdPrice` stays a string in `Balance` and is parsed by `computeUsd`; a bad price shows "USD n/a" / "—" instead of failing the whole balances response — reject the response — balances (real money) are still correct and visible; amounts themselves are strict (BAD_RESPONSE).
- Step 2: `decimals` must be an integer 0..36 — accept any number — sanity bound against absurd values.
- Step 2: Claim/claim-options/activity parsers take `decimals` (activity: a map from balances) because those responses don't carry it; activity item for an unknown asset = BAD_RESPONSE.
- Step 2: Token: `secureTextEntry` input, trimmed, saved to localStorage key `cashmine.token`; Home is keyed by token so a new token never shows the previous account's data; 401 never clears the token.
- Step 2: Pull-to-refresh: RefreshControl on native; on web (RNW renders RefreshControl as a no-op View) a small touch-drag handler at scrollTop 0 — skip it on web — the app ships as web on phones.
- Step 2: Gradient buttons via `expo-linear-gradient` — CSS gradient — RNW 0.21 has no backgroundImage style; Expo module preferred per AGENTS.md.
- Step 2: Font = system stack led by Inter (no webfont download) — load Inter via expo-font — fewer deps, fast first paint.
- Step 2: Removed template files + `scripts/reset-project.js` (would wipe the app if run); left unused template npm deps (expo-device, expo-symbols, …) installed — not imported, so not bundled.
- Step 2: `.env` is loaded by the Expo CLI, but only `EXPO_PUBLIC_*` vars are inlined; verified the web export does not contain the token.
